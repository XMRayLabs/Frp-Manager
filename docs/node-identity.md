# 设备身份与名称

客户端和服务端使用专属设备密钥认证。名称用于显示和配置关联；修改名称不会更换密钥或设备身份。

客户端名称格式为“所属用户.c.名称”，服务端为“所属用户.s.名称”。所属用户以数据库记录为准，不能通过修改前缀转移设备。自动接入先生成随机名称，随机名称不是设备密钥。

例如设备原命令使用 `-s <设备密钥> -i admin.c.abc`，面板改名为 `admin.c.def` 后，原命令继续连接该设备。`-i` 的旧值不会覆盖面板名称；旧名称立即可以被其他设备使用，不保留名称别名。

删除客户端会清理其子配置与隧道并撤销认证。普通重启继续使用保存的身份，已经删除的设备会认证失败，不会自动重新注册。新版桌面客户端和 Android 客户端重新“保存并连接”时，会发起明确的接入尝试：旧身份有效则继续使用；面板明确告知旧身份失效时，才用接入令牌重新注册。网络错误不会清空身份。

命令行重新接入可额外传入 `--enrollment-attempt <本次新生成的UUID>`，同时提供接入令牌。安装服务时保留这个固定值，普通重启不能每次重新生成。环境变量对应 `CLIENT_ENROLLMENT_ATTEMPT`。GUI 自动管理该值。

升级顺序：先升级管理面板，再升级设备程序。旧设备的专属密钥命令兼容改名；自动恢复失效缓存需要新版设备程序。首次启动新版面板会自动补充不可变设备标识，并迁移、清理旧名称别名记录。旧 FRP 内核需要的运行实例键仅作为内部兼容信息，不作为名称别名或认证依据。

更新数据库前应保留现有数据库备份。本次改动随 1.0.5 发布，详见仓库根目录更新日志。

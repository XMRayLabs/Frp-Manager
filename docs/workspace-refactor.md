# 工作空间与客户端重构

本次围绕常用的“接入设备 → 配置隧道 → 查看状态”流程调整，涉及管理面板、桌面/移动端共享 React 界面、原生接入桥接、配置与后端状态探测。

## 使用变化

- 首页提供四项节点统计和三步接入引导；未获取到统计显示 `—`，不会把加载中误显示成零。
- 客户端、服务端、隧道与流量为主要导航；WireGuard、控制台、日志、函数等收在高级工具中。
- 节点页面以自动接入为主要操作，手动创建收起。搜索输入 350ms 后自动生效，支持回车和清空。
- 普通节点列表按页读取（默认 10 条）；全局筛选时分批读取完整目录，每批 200 条，保留全局配置/在线状态筛选。普通模式的列排序只对当前页生效，界面已标明。
- 列表增加加载、错误重试和空状态，手机宽度不再撑宽整个页面；宽表格在内部横向滚动。
- 桌面/移动共享界面采用“粘贴命令 → 确认并连接”，高级字段默认折叠。支持 `-j` / `--join-token` 及已有 ID/密钥命令，自动推导 WS/WSS 地址。
- 客户端刷新运行状态不会重载并覆盖正在编辑的配置，离开或切换未保存配置时提示；保存并连接合并为一个主要操作，服务维护收起。

## 性能与正确性

- QueryClient 生命周期上移到应用根部，页面沿用同一缓存；账户查询键不再带路由。登录成功清理旧缓存。
- 默认查询保鲜 30 秒；普通节点目录每 10 秒刷新当前页，高级全局目录每 30 秒刷新；后台标签页不持续轮询。
- 节点状态请求每批最多 200 个 ID，最多 4 批并行；ID 去重，避免过大的数据库 IN 查询。
- 状态探测先占用 32 个名额之一，再启动 goroutine。繁忙时跳过本次探测，后续轮询重试，不创建等待名额的无限协程队列。
- 客户端轮询通过完成后再安排下一次的方式运行，隐藏窗口不请求，执行服务操作时暂停普通轮询。
- 客户端/服务端分页查询固定按 ID 排序，避免数据库默认顺序导致翻页不稳定。
- 新增 `CLIENT_JOIN_TOKEN` 供原生服务配置传递自动接入令牌，配置打印及执行结果脱敏。GUI 管理的独立桌面服务恢复启动检查更新；Android 包内核心仍按 APK 更新。

## 验证记录

通过：

- 管理面板生产构建（28 个静态页面）。
- 客户端 TypeScript 与 Vite 构建。
- 完整内核及精简客户端内核 Windows 编译。
- conf、shared、platform、client、server、rpc、upgrade、utils 等相关 Go 回归。
- Electron 服务桥接测试 10 项（含模拟核心执行退出码检查）。
- 命令解析测试 3 项；分批目录加载及并发上限测试 3 项。
- 无头 Edge 隔离模拟数据验收：导入命令、保存配置、等待轮询后仍保留编辑、首页导航、两页分页、缓存复用、390px 手机宽度。没有页面运行错误。

浏览器实际记录：从首页进入客户端并切换下一页，只发出 1 次账户请求；目录分别请求 `page=1,pageSize=10` 和 `page=2,pageSize=10`。这证明了请求行为变化，不代表真实生产环境的整体提速倍数。

未验证：真实公网跨设备连接、实际 Release 替换升级、管理员权限下系统服务安装/重启、macOS 签名分发和 Android APK 原生编译。Android Java 侧已接上令牌与配置目录，但不将 Web 构建算作 APK 验证。

高级全局筛选仍需载入全部节点元数据，超大规模部署应继续迁移到服务端筛选接口。当前目录不是 Git 仓库；重构前关键源码备份位于工作区 `.frp-task-tools/refactor-backup`。

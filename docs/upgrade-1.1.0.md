# 1.1.0 语系账号体系

网站管理员在“语系管理”创建语系和语系管理员，再分配服务端。语系管理员可以批量创建普通用户，或生成绑定本语系的邀请码。每位非网站管理员只归属一个语系；一个语系可以有多名管理员。

## 权限

| 操作 | 网站管理员 | 语系管理员 | 普通用户 |
| --- | --- | --- | --- |
| 创建语系、任免管理员、迁移用户 | 本站 | 不支持 | 不支持 |
| 批量创建、禁用、重置成员密码 | 本站 | 本语系普通用户 | 不支持 |
| 创建、配置、分配服务端 | 本站 | 仅使用已分配服务端 | 仅使用已分配服务端 |
| 客户端、隧道配置 | 本站 | 本语系所有设备 | 自己及语系共享设备 |
| 私有设备、设备密钥、终端、升级 | 本站 | 本语系所有设备 | 自己的设备 |
| Workers、WireGuard | 本站 | 本语系资源 | 自己的资源 |

“本站”始终受原有 TenantID 边界约束。语系和旧权限组是不同概念，旧权限组不能跨过语系或私有设备边界。

共享默认关闭。开启后，本语系成员可以共同配置隧道；私有设备除外。共享设备的认证、TLS 私钥和执行类能力不对普通共享成员开放。隧道归设备主人所有，管理记录保存实际操作者。

## 用户迁移、撤权与离线设备

用户迁移先预览目标语系缺少哪些服务端授权，再确认。原设备名称、设备密钥和私有设置保持不变；旧权限组、旧直接授权及该用户签发的邀请码清除。目标语系无权使用的服务端对应隧道停止，原隧道配置保留。旧登录会话失效。

撤销服务端授权同样先预览再确认。数据库保存停止状态，在线设备会收到停止指令；未送达或离线设备由周期性拉取配置及下次接入恢复同步。重新分配服务端不会自动恢复旧隧道，需在隧道列表逐条启动。离线本身不视为故障。

禁用账号阻止面板登录与新的自动接入，不撤销已存在的设备认证，已有隧道继续运行。上级管理员仍可管理这些设备。密码重置为邮箱后必须首次改密；旧会话和 API 登录令牌失效，固定设备接入令牌独立管理。

## 从 1.0.x 升级

1. 暂停管理面板写入并备份数据库、配置、证书和 Docker 数据卷。使用 MySQL/PostgreSQL 时，由数据库管理工具制作一致性快照。
2. 先用备份副本启动 1.1.0 验证。SQLite 文件数据库首次迁移前自动生成同目录 `.before-1.1.0-时间.bak` 快照；快照失败则停止启动。内存数据库不生成快照。
3. 原有普通用户进入各自租户的“默认语系”。旧可用服务端转成明确语系授权；此迁移只执行一次，之后重启不会恢复已撤销授权。原设备名称和密钥保持不变。
4. 网站管理员创建目标语系、管理员并分配服务端，然后使用迁移预览分批迁移用户。
5. 验证两组之间无法读取或修改设备、共享开关和私有覆盖、批量创建与首次改密、撤权与离线重连，再推广。

回滚必须停机并恢复升级前的完整数据库及对应 1.0.x 镜像。不要用旧二进制直接运行已经迁移的数据库。

版本号为 **1.1.0**。Docker 仓库继续使用 `sakurame1/frp-manager`，数据目录和已有发布产物命名规则保持不变。正式推送和发布需单独执行。

## PostgreSQL

生产多用户部署支持 PostgreSQL；升级旧 SQLite 时请先停机迁移，再启动新数据库配置。参见[部署及迁移说明](postgresql.md)。Docker 镜像和原 /data 挂载不变。
